# Hermes in Holospaces — documentation-as-code runbook

This directory is the **executable** contract for lifting the `hermes-web` dashboard onto the os-holo /
holospaces substrate. The prose is the spec; the spec is run. Nothing here is aspirational without a
witness: each behavior is a Gherkin scenario that executes against the real artifacts and emits a JSON
witness, and every scenario is either **green** (proven now) or **pending** (a documented behavior with
its exact external dependency recorded — never silently skipped).

- Full design + verified-against-source plan: [`.plans/hermes-holospaces-implementation-plan.md`](../../.plans/hermes-holospaces-implementation-plan.md)
- Reference substrate (consumed unchanged): os-holo (`humuhumu33/os-holo`, vendored at [`holo/`](../../holo)),
  holospaces (`Hologram-Technologies/holospaces`).

## The method

Documentation-as-code + strict behavior-driven testing:

1. **One pipeline, run identically locally and in CI** (no CI-only magic):

   ```
   (cd web && npm ci)
   tools/holo/build-app.sh                                   # Vite base=./ → place → relock seal
   FRAME=holo APPS=apps OUT=_site node tools/holo/assemble-site.mjs hermes   # fold into frame → _site
   node tools/holo/bdd.mjs features/holospaces               # strict behaviour gate (fail-closed)
   ```

2. **Strictness** (`tools/holo/bdd.mjs`): an undefined or failing step in a normal scenario fails the
   suite (exit 1). A `@pending` scenario is red-by-design; its steps throw `PENDING: <dependency>` and
   are recorded, not counted as failures. A `@pending` scenario that unexpectedly goes all-green is
   itself flagged — pending must stay honest.

3. **Witnesses** are the audit trail: `tools/holo/witness/bdd.json` (behaviors),
   `_site/holo-witness-assemble.json` (registration). The Pages deploy is gated on the behavior witness.

## Stage status (this commit)

- **Stage A — app object on Pages: GREEN.** Built (`base=./`), sealed (root κ
  `did:holo:sha256:eaeaa1af…`, 25-file closure, idempotent), registered into the frame (`os-closure`
  `apps[]` 32→33, closure 477→501, catalog updated), behavior-gated, and wired into a Pages workflow
  deploying from `hermes-web`. The transport seam is unified (typecheck clean).
- **Stage B — guest runtime: PENDING.** Needs the `linux/riscv64` OCI image (buildx) + a riscv64
  kernel image; boot via `holospaces-web boot_devcontainer_routed_opfs_streamed` (DTB is generated by
  the Boot Orchestrator, not supplied).
- **Stage C — transport binding: SEAM + WIRE GREEN, LIVE ROUND-TRIP PENDING.** The full transport is
  implemented and BDD-green at the protocol level: `api.ts` exposes the REST + socket swap points
  (`setFetchImpl`/`setSocketFactory`/`resetTransport`); `holo-wire.mjs` is the proven HTTP/1.1 +
  RFC-6455 codec (REST reads/verbs, chunked reassembly, WS upgrade + masked framing all round-trip in
  the suite); `holo-transport.ts` layers `fetch`/`WebSocket` semantics over the `GuestBridge` and
  installs them via `installHologramTransport`. Ingress itself is first-class (`Workspace.dial_guest`,
  witnessed by holospaces `CC-33`). The one RISC-V `routed_opfs + enable_loopback` boot fn HL-C needed
  is now **authored, carried in-repo as a patch, and compiled for wasm32** (HL-4 — green;
  `tools/holo/patches/holospaces-web-riscv-loopback.patch`). Remaining pending (HL-C target): the live
  round-trip against a booted guest (HL-B).

> **Testing follows holospaces' V&V framework** (the shared devcontainer): see [`vv/README.md`](../../vv/README.md)
> and the [conformance catalog](conformance.md). `vv/suites/` gate (green: HL-1..HL-4); `vv/targets/` are
> expected-RED until built (HL-B/HL-C/HL-D). Run `just vv`.
- **Stage D — convergence: PENDING.** Egress via `boot_devcontainer_net` relay or direct CORS fetch
  (COEP `credentialless`); full learning-loop persistence on the OPFS κ-store.

The pending items are blocked on out-of-repo dependencies (a riscv64 toolchain/kernel, a Rust shim in
`holospaces-web`, a relay), not on undefined design — each is specified to the function/ADR in the plan
and recorded as a `PENDING` reason in the witness.
